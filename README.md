# Workbench

A single-user local workspace for Markdown and Jupyter notebooks, mixed-file projects, daily planning, calendars, student supervision, and faculty conversations. Application code and private workspace data are stored separately.

## Start

Requires Node.js 22+ and npm. macOS and Linux support interactive terminals through node-pty. Install native build tools if a prebuilt PTY helper is unavailable.

```sh
npm ci
npm start
```

Open http://127.0.0.1:3210. The default private workspace is `~/Documents/My Notebook`.

```sh
npm start -- --workspace "/path/to/My Notebook"
# Or, after npm run build:
WORKBENCH_WORKSPACE="/path/to/My Notebook" npm run serve
```

The `--workspace` option overrides the environment variable. Set `PORT` to change the localhost port. Application assets always come from this installation, independently of the selected workspace. Stop with Ctrl+C.

## Files and editing

Collections supports Markdown, Jupyter, ordinary UTF-8 text, images, PDFs, and other files. Markdown has Edit/Preview/Split modes with sanitized rendering, tables, task checkboxes, math, and synchronized scrolling. Text files use syntax highlighting where available; files up to 5 MB can be edited. UTF-8 BOMs and newline conventions are retained. Non-UTF-8, binary, and larger text files are download-only. HTML and SVG are shown as source, never executed as previews.

Changes autosave after 750 ms. Cmd/Ctrl+S saves immediately. Revision conflicts retain drafts and require explicit reload or overwrite. Browser drafts help recovery but do not replace backups. Vim is enabled by default; Esc or Ctrl+[ leaves Insert mode. Tab indents; Shift+Tab removes indentation. Ctrl+M (Shift+Alt+M on macOS) toggles Tab focus navigation.

Search includes active and archived filenames and supported text contents, plus Daily, Student, Group, and Faculty records. Trash is excluded. PDF/image/binary contents are not indexed. Jupyter searches cell source rather than saved outputs.

Sidebar icons appear on hover/focus and act on their own file or folder. Pin, rename/move, archive, and trash files; create notebooks or subfolders. Archive and Trash support read-only previews and restoration with collision dialogs. Folders retain all nested files, including hidden/generated files omitted from navigation. Nothing in Trash expires automatically.

Cmd+B toggles the sidebar and Cmd+J the workspace terminal on macOS; use Ctrl+B/J elsewhere. Each active file has a separate shell session. Hide/switch/reload preserves sessions while the server runs; Close Session and server restart terminate shells and their children. Eight live sessions are allowed. Ordinary files start in their containing Collections folder; imported Jupyter working-directory mappings are retained. Conda activation in the shell is separate from Python kernels. Stored Archive/Trash files cannot start terminals or kernels.

## Private storage and backups

A workspace contains `collections/` and `.notebook/`. The latter stores Student, Group, and Faculty records, Daily, calendars, timetables, backups/versions, attachment mappings, Archive, Trash, and import settings. **It is essential user data, not a disposable cache.** Back up the entire workspace. Hidden folders and Git-ignore rules do not provide encryption. Do not store sensitive credentials here unless you accept ordinary unencrypted files.

This public repository includes application code and synthetic fixtures only. Never copy private workspaces, import exports, logs, or previous private Git history into it. Use a separate private repository or backup system for personal files.

Legacy workspaces with a root `notebook-import.json` remain readable. `npm run migrate -- /path/to/workspace` imports remaining Markdown/Jupyter notes and records provenance in `.notebook/import-manifest.json`; review source folders before importing. It does not scan application instructions as user notes.

For an existing legacy workspace, with its server stopped, `node scripts/organize-workspace.mjs /path/to/workspace --dry-run` reviews the migration. Omit `--dry-run` to merge root circuit helpers into Collections, import the explicit legacy password note privately, and move timetable JSON imports/provenance into `.notebook/`. macOS .DS_Store files stay in their original folders; generated bytecode moves with its project but stays hidden. The helper verifies hashes, stops on collisions, and resumes an interrupted operation through its private journal. This helper never publishes workspace data.

## Daily, Calendar, and Students

Daily task rows use a chevron for Details and a trash icon for Remove. Expanded details have a sage background and distinct Task settings, Timing, Task notes, Subtasks, and Task history blocks. Remove replaces cancellation in Details; Undo and reopening remain available. Optional Deadline and Reschedule pickers start in the current local month when empty, or the selected month for existing dates. Browsing months and closing do not assign a date; Today selects today, Clear unsets it, and Reschedule applies the staged date.

Daily keeps dated task histories, subtasks, categories, notes, and completion states. **Import from Markdown** selects a source note and inclusive date range, previews changes, and applies them with source/Daily revision checks. Repeated imports do not duplicate dates. Import preferences are stored privately.

Calendar supports events, student conversations, class overlays, conflict review, and local reminders. Students supports profiles, meeting preparation, meeting records, goals, and timetable imports. Scheduling a student conversation creates a Calendar event in the Students category and a linked Daily record titled with the student’s name. Completing or reopening that Daily record updates Calendar’s completion indicator. Student note fields show raw Markdown while editing, then render the formatted preview in the same area after Done editing. Existing rich-text notes remain readable and editable. Each supervision record includes a Correction field. The Supervision Record section sits directly below Next Conversation, independently of the height of the Objectives sidebar, on desktop and mobile. Exports and private import files remain workspace data. The fixture under `tests/fixtures/` uses invented people and schedules.

### Faculty conversations

**Faculty** keeps professional profiles, conversation preparation, conversation records, and follow-up tasks without objectives or course timetables. Only a member’s name is required; institution, department, position/title, email, research areas, and Markdown profile notes are optional. Next Conversation sits directly above Conversation Records on desktop and mobile. Start conversation moves the agenda into Discussion and clears preparation in a single save. Records include Decisions and Correction; tasks have an owner (Me or Faculty member), due date, and completion state, with unfinished tasks linked from preparation.

Scheduling defaults to a 30-minute conversation in the **Faculty** category. It checks your Calendar only and uses inline conflict acknowledgment; it does not establish your colleague’s availability. Calendar and Daily link back to the member. Rescheduling retains the linked Daily record; completing or reopening that record updates Calendar. Deleting a booking preserves conversation notes and follow-up tasks. Profiles and notes use the same Markdown editing, autosave, draft recovery, revision checks, archive/restore, search, export, and duplicate-tab protections as Students. Faculty documents and version history stay in `.notebook/faculty/` and `.notebook/faculty-versions/` inside the private workspace.

### Group sessions

**Group** keeps shared supervision in a single record, linked from the participating students’ pages. Create a group from existing students and select a student leader. Students can belong to several groups; changing members or leaders preserves past sessions and action assignments.

Prepare a **Workshop** or **Roundtable** under Next Session. Workshops initially select every member; roundtables initially select the leader. Click names to change the participants, keeping at least one selected. Starting or scheduling transfers the preparation into a session record. Discussion, Decisions, and Correction use raw Markdown while editing and render after **Done editing**. Objectives support milestones, deadlines, statuses, and links to sessions and actions. Follow-up actions can belong to named students, the group, or the supervisor.

Scheduling checks every selected participant’s class timetable and existing Calendar bookings, shows incomplete availability, and offers shared available times. Conflicts require explicit confirmation and are checked again on save. Group bookings create one linked Calendar event and Daily record in the **Group** category. Rescheduling retains the record’s identity; Daily completion and reopening update Calendar. Cancelling a booking keeps its supervision notes. Open the authoritative group session from Calendar, Daily, student overviews, or global search.

Sessions may have optional PDF, PPT, PPTX, or Keynote attachments, up to 100 MB per file. PDFs have a preview link; other presentations download in their original format. Files, group documents, and revision history stay in the private workspace under `.notebook/`. Detaching an attachment preserves the file for record versions. JSON exports contain metadata; download the presentation files separately. Group drafts, save conflicts, and duplicate editing tabs use the same protection as Students.


To import a timetable document into an existing student record, stop the server and run:

```sh
node scripts/import-timetable.mjs /path/to/import.json /path/to/workspace
```

## Jupyter

Select a discovered local Conda/project Python environment with `ipykernel` and `jupyter_client`. Start, run, interrupt, restart, and stop kernels from the notebook. Python variables persist per session; saved outputs remain in the notebook. Unsupported widgets/output payloads are preserved. The app does not install Python packages into user environments automatically.

## Development and validation

```sh
npm test
npm run build
npx playwright install chromium
npx playwright test
```

Tests create isolated synthetic workspaces. Optional Python execution checks require `WORKBENCH_TEST_PYTHON` to point to an executable Python in a virtual/Conda environment with Jupyter packages; otherwise they are reported as skipped. Use `PLAYWRIGHT_CHANNEL=chrome` to test with installed Chrome. CI provides a test Python environment.

After frontend changes, rebuild and refresh tabs with saved drafts. After backend/configuration changes, restart the server, checking active shell/kernel work first. The application listens only on `127.0.0.1`; do not expose it publicly. This project is MIT licensed; bundled libraries retain their own licenses.
